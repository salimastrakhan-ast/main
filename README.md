# Маяк

Мессенджер: бэкенд на Go, клиент на Flutter под iOS, Android и веб.

Личные чаты и группы, сообщения в реальном времени, доставлено и прочитано,
«печатает», статус в сети, редактирование и удаление, вложения, работа
офлайн с досылкой написанного.

## Быстрый старт

Нужны Go 1.24, Flutter 3.35 и Docker.

```bash
make up      # Postgres, Redis и MinIO в контейнерах
make run     # сервер: миграции применятся сами
```

Сервер на `http://localhost:8080`. Проверка живости:

```bash
curl http://localhost:8080/healthz
```

Вход без SMS-провайдера: в режиме разработки код возвращается прямо в ответе.

```bash
curl -X POST http://localhost:8080/v1/auth/request-code \
  -H 'Content-Type: application/json' -d '{"phone":"+7 999 123-45-67"}'
# {"phone":"79991234567","expires_in":300,"dev_code":"123456"}

curl -X POST http://localhost:8080/v1/auth/verify \
  -H 'Content-Type: application/json' \
  -d '{"phone":"+79991234567","code":"123456","platform":"cli"}'
```

Клиент:

```bash
make app-get     # зависимости
make app-gen     # кодогенерация Drift
make app-web     # веб-сборка
cd app && flutter run   # или на подключённом устройстве
```

## Тесты

```bash
make test        # бэкенд: юнит и интеграционные, нужен make up
make app-test    # клиент
make app-analyze # анализатор Dart
make e2e         # живой клиент против живого сервера
```

Интеграционные тесты работают против настоящих Postgres и Redis, а не
заглушек. Проверяется ровно то, что делает база: выделение номера под
блокировкой строки, откат номера при конфликте, уникальные индексы. На моках
всё это прошло бы успешно и в сломанном виде.

## Настройки

Значения по умолчанию рассчитаны на `make up`, поэтому локально сервер
запускается без единой переменной.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `MAYAK_ENV` | `dev` | В `dev` код подтверждения возвращается в ответе API |
| `MAYAK_HTTP_ADDR` | `:8080` | Адрес прослушивания |
| `MAYAK_DATABASE_URL` | локальный Postgres | Строка подключения |
| `MAYAK_REDIS_URL` | локальный Redis | Строка подключения |
| `MAYAK_JWT_SECRET` | — | **Обязателен вне `dev`** |
| `MAYAK_ACCESS_TTL` | `15m` | Срок жизни access-токена |
| `MAYAK_REFRESH_TTL` | `720h` | Срок жизни refresh-токена |
| `MAYAK_SMSRU_API_KEY` | — | Без него коды уходят только в лог |
| `MAYAK_S3_ENDPOINT` | `localhost:9000` | Хранилище файлов |
| `MAYAK_MAX_UPLOAD_MB` | `50` | Предел размера вложения |
| `MAYAK_CORS_ORIGINS` | пусто | Нужен только веб-клиенту, через запятую |
| `MAYAK_TRUST_PROXY` | `false` | Включать, только если перед сервером свой прокси |

Про `MAYAK_TRUST_PROXY`: заголовок `X-Forwarded-For` подделывается кем
угодно. Доверять ему можно ровно тогда, когда его перезаписывает ваш
собственный прокси, иначе лимиты по IP обходятся одной строкой в запросе.

## Состояние

Работает и проверено: вход по номеру в любом формате записи, личные чаты и
группы, доставка в реальном времени, добор пропущенного после обрыва связи,
идемпотентность отправки, роли в группах, отметки прочтения, вложения.

Не сделано осознанно: каналы, сквозное шифрование, звонки, боты, реальные
пуши. Список с объяснениями — в конце
[документа об архитектуре](docs/architecture.md).
