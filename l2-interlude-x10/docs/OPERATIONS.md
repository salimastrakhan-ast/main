# Эксплуатация сервера

---

## Ежедневные команды

```bash
make status              # контейнеры, порты, онлайн, паузы GC, последние ошибки
make online              # кто сейчас в игре
make logs                # логи игрового сервера, Ctrl+C для выхода
make backup              # копия обеих баз
make restart             # перезапуск с корректным сохранением персонажей
```

### Про правильный перезапуск

`make restart` даёт серверу 60 секунд на завершение: за это время он
сохраняет персонажей, инвентари и позиции. Если убить контейнер жёстко
(`docker kill`, `down --timeout 0`), последние минуты игры у всех, кто был
онлайн, потеряются — вплоть до предметов, полученных после последнего
автосохранения.

Перед плановым рестартом предупреди игроков через ГМ-команду `//announce`.

## Резервные копии

Настрой до открытия сервера, а не после первой потери данных.

```bash
make backup                                   # разовая копия
./scripts/backup.sh --restore backups/l2-20260101-030000.sql.gz
```

Копии снимаются с `--single-transaction`: игроков это не блокирует,
снимок консистентный, сервер можно не останавливать.

Автоматизация — строка в cron:

```cron
0 5 * * * cd /путь/к/l2-interlude-x10 && ./scripts/backup.sh >> logs/backup.log 2>&1
```

Хранится последние 14 копий (меняется переменной `BACKUP_KEEP`).
Копии лежат на той же машине — для сервера, который жалко потерять,
настрой отправку куда-то ещё.

**Восстановление перезаписывает базы целиком** и требует подтверждения.
Всё, что произошло после снятия копии, будет потеряно.

## Аккаунты и права

```bash
make gm CHAR=ИмяПерсонажа        # выдать права ГМ (уровень 8)
./scripts/account.sh gm Имя 0    # снять права
./scripts/account.sh ban логин   # забанить аккаунт
./scripts/account.sh unban логин
./scripts/account.sh accounts    # список аккаунтов
```

Уровень доступа должен быть описан в `dist/game/config/AccessLevels.xml`;
по умолчанию 8 — это Head Game Master. Права применяются после перезахода
персонажем.

Базовые ГМ-команды в игре: `//admin` (панель), `//gmlist`, `//announce`,
`//teleport`, `//spawn`, `//reload`. Полный список того, что разрешено
какому уровню, — в `dist/game/config/AdminCommands.xml`.

Отдельной команды «создать аккаунт» нет намеренно: при
`AutoCreateAccounts = True` аккаунт создаётся при первом входе, и пароль
хэшируется тем алгоритмом, который использует именно твоя сборка.
Вписанный руками хэш — самая частая причина «неверного пароля» на ровном месте.

## Имя сервера в списке

Номер задаётся в `.env`:

```ini
L2_SERVER_ID=1
```

Клиент показывает не номер, а имя из таблицы имён (Bartz, Sieghardt, Kain и
далее). Какому номеру какое имя соответствует — зависит от сборки; смотреть
в данных логин-сервера:

```bash
grep -ril "bartz" dist/login/ | head
```

Если номер уже занят другой регистрацией, сервер в списке не появится —
см. [TROUBLESHOOTING.md](TROUBLESHOOTING.md), раздел про пустой список.

## Изменение рейтов на живом сервере

```bash
# 1. правим config/profiles/x10-classic.conf
./scripts/configure.sh --dry-run    # 2. смотрим, что изменится
make configure                      # 3. применяем
make restart                        # 4. перезапускаем
```

Часть настроек подхватывается ГМ-командой `//reload config` без рестарта,
но надёжнее перезапуск.

Никогда не правь `dist/game/config/*.ini` напрямую: следующая же сборка
эмулятора затрёт правки. Всё, что нужно сохранить, должно жить в профиле.

## Обновление эмулятора

```bash
make backup                         # 1. обязательно
./scripts/build-server.sh --update  # 2. свежие исходники и пересборка
make configure                      # 3. вернуть свои настройки
make restart
```

Прежние конфиги сохраняются в `backups/config-<дата>/` — есть с чем сравнить,
если после обновления поведение изменилось.

Обновляться имеет смысл: исправления багов Interlude выходят регулярно.
Но не в пятницу вечером и не перед осадой.

## Безопасность

Что уже сделано в стенде:

- порт базы опубликован только на `127.0.0.1` — снаружи он недоступен;
- пароли задаются в `.env`, который не попадает в git;
- у логин-сервера включён бан по числу неудачных попыток входа.

Что нужно сделать самому:

1. **Смени пароли** в `.env` до первого запуска. Пароли из `.env.example`
   годятся только для локальной проверки.
2. **Файрвол**: открой ровно 2106 и 7777.

```bash
sudo ufw allow 2106/tcp
sudo ufw allow 7777/tcp
sudo ufw enable
```

3. **Не пробрасывай 3306 наружу.** Никогда. Для доступа к базе с рабочей
   машины используй SSH-туннель:

```bash
ssh -L 3306:127.0.0.1:3306 user@сервер
```

4. **Выключи автосоздание аккаунтов**, когда сервер перестанет быть «для своих»:
   в `config/profiles/_network.conf` → `AutoCreateAccounts = False`.
5. **Обнови систему** и держи Docker свежим.

## Мониторинг

Минимально достаточный набор — `make status`. Он показывает то, что реально
предсказывает проблемы: паузы GC, онлайн, потребление памяти, свежие ошибки.

Более серьёзный вариант — раскомментировать блок JMX в
[`jvm/gameserver.options`](../jvm/gameserver.options) и подключиться
VisualVM через SSH-туннель. Порт JMX наружу не открывать.

Логи:

| Что | Где |
|---|---|
| Игровой сервер | `make logs`, `dist/game/log/` |
| Логин-сервер | `make logs-login` |
| База | `make logs-db` |
| Паузы GC | `dist/game/log/gc.log` |
| Медленные запросы | `docker compose exec db tail -50 /var/log/mysql/slow.log` |

Логи Docker ограничены 50 МБ на файл и 5 файлами — место не забьётся.

## Когда пора увеличивать ресурсы

| Признак | Что делать |
|---|---|
| Паузы GC растут выше 200 мс | поднять `GAME_HEAP` |
| В `slow.log` появились запросы | поднять `DB_BUFFER_POOL` |
| CPU в потолке при большом онлайне | смотреть `PathFinding`, кастомные скрипты |
| Диск в потолке | переезжать на SSD/NVMe, это не настраивается |

Ориентиры по онлайну и памяти — таблица в [ANTI-LAG.md](ANTI-LAG.md).
