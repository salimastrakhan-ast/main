# Lineage 2 Interlude x10 — сервер под ключ

Готовый стенд для собственного сервера L2 Interlude с рейтами x10 в классическом
духе: MariaDB + LoginServer + GameServer в Docker, настройки рейтов профилем,
одна команда на установку.

```bash
cp .env.example .env      # поменяй пароли и L2_EXTERNAL_IP
make install              # сборка, конфиги, база, запуск
```

---

## Сначала — честный ответ на вопрос

Ты просил «самую официальную сборку, без багов и лагов». Тут три вещи, которые
лучше знать до старта, чем через месяц.

**Официальных серверных файлов Interlude не существует в открытом доступе.**
NCSoft никогда их не публиковала. Всё, на чём работают частные серверы —
это эмуляторы: программы, написанные с нуля по наблюдаемому поведению
официального сервера. Их несколько, и «официальность» тут измеряется тем,
насколько близко к ретейлу воспроизведены формулы и механики.

**Сборки без багов не бывает.** Interlude — это игра на сотни тысяч строк
логики: скиллы, осады, олимпиада, крафт, петы, эпики. Любой эмулятор в чём-то
расходится с оригиналом. Реалистичная цель — не «ноль багов», а «расхождения
редкие, известные и чинятся апдейтом». Этот стенд собирает сервер из живого
исходного кода, а не из архива десятилетней давности с форума, — поэтому
исправления приходят к тебе командой `make build --update`.

**Лаги почти всегда не в эмуляторе.** За годы на форумах устоялось, что
«сборка лагает». На практике источники тормозов в порядке убывания частоты:
настройки БД по умолчанию, паузы сборщика мусора JVM, отсутствие геодаты,
слабый диск на VPS. Всё четыре пункта в этом стенде закрыты заранее —
подробности в [docs/ANTI-LAG.md](docs/ANTI-LAG.md).

### Interlude или Classic — это разные игры

В названии сервера ты написал «Interlude» и «классик». Это разные хроники:

| | Interlude (C6) | L2 Classic |
|---|---|---|
| Год | 2007 | 2018+ |
| Что это | последняя хроника «старой» эпохи | современная переработка ранних хроник |
| Протокол клиента | 746 | 388+ |
| Клиенты | несовместимы между собой | |

Стенд по умолчанию собирает **Interlude (CT_0)** — то, что и просили. Если
имелась в виду современная L2 Classic, укажи в `.env` нужный каталог, например:

```ini
L2_CHRONICLE=L2J_Mobius_Classic_3.5_TalesUntold
```

Остальное — рейты, база, запуск — работает одинаково. Точное имя каталога
скрипт сборки подскажет, если ошибиться.

### Какой эмулятор

По умолчанию берётся **L2J Mobius** — из свободных проектов он единственный,
который продолжают активно развивать по всем хроникам сразу, и его Interlude
ближе всего к ретейлу. Альтернатива — **aCis**: он заточен ровно под Interlude
и код там чище, но развивается медленнее и часть ревизий закрыта.

Исходники Mobius лежат на **GitLab**, а не на GitHub:
`https://gitlab.com/MobiusDevelopment/L2J_Mobius.git`. В репозитории 38 хроник;
Interlude — это каталог `L2J_Mobius_CT_0_Interlude` (CT_0 = Chronicle Throne 0).
Скачивается только он, а не весь репозиторий.

Стенд не привязан к Mobius. Любой эмулятор с ant/maven/gradle-сборкой
подставляется через `.env`:

```ini
L2_SOURCE_REPO=https://github.com/<кто-то>/<его-эмулятор>.git
L2_CHRONICLE=<каталог хроники>
```

## Что нужно

| | Минимум | Комфортно |
|---|---|---|
| ОЗУ | 4 ГБ | 8–16 ГБ |
| Диск | 10 ГБ свободных | 40 ГБ SSD/NVMe |
| CPU | 2 ядра | 4+ ядра |
| Софт | Docker + Docker Compose + `make` | то же |

Java на хосте не нужна: Mobius компилируется под JDK 25, и сборка идёт
в контейнере с готовым JDK. Собственные образы стенд не собирает,
поэтому и `buildx` не требуется.

Диск обязательно SSD. На обычном HDD база становится узким местом уже
на полусотне игроков.

Клиент игры Interlude — твой собственный, легально полученный. Стенд его
не содержит и не скачивает: это серверная часть.

## Установка

**1. Настройки**

```bash
cp .env.example .env
```

Обязательно поменяй:

- `DB_ROOT_PASSWORD` и `DB_PASSWORD` — пароли базы;
- `L2_EXTERNAL_IP` — адрес, по которому к серверу подключаются игроки.
  `127.0.0.1` — только с этой же машины, `192.168.x.x` — по локальной сети,
  внешний IP или домен — из интернета.

**2. Установка одной командой**

```bash
make install
```

Что произойдёт: скачаются исходники эмулятора (несколько ГБ, один раз),
соберутся в `./dist`, применится профиль x10, создадутся и наполнятся базы,
поднимутся контейнеры. Первый прогон — 15–40 минут, почти всё время занимает
загрузка исходников.

Те же шаги по отдельности, если что-то пошло не так:

```bash
make build       # скачать и собрать
make configure   # применить рейты и сетевые настройки
make db-init     # создать базы (стирает данные!)
make up          # запустить
```

**3. Проверка**

```bash
make status
```

Должны отвечать порты 2106 (логин) и 7777 (игра).

**4. Клиент**

См. [docs/CLIENT-SETUP.md](docs/CLIENT-SETUP.md) — там про `l2.ini`, версию
протокола и геодату.

**5. Права ГМ**

Зайди в игру (аккаунт создастся сам при первом входе), создай персонажа, потом:

```bash
make gm CHAR=ИмяПерсонажа
```

Перезайди персонажем — станут доступны `//admin` и остальные команды.

## Рейты

Профиль x10 лежит в [`config/profiles/x10-classic.conf`](config/profiles/x10-classic.conf).
Кратко, что получается:

| Параметр | Значение | Почему так |
|---|---|---|
| Опыт и SP | **x10** | то, ради чего затевался x10-сервер |
| Адена | **x10** | задаётся множителем по id предмета (57), своего RateDropAdena у Mobius нет |
| Дроп с мобов | шанс x5, количество x2 | по итогу ~x10, но редкое остаётся редким |
| Спойл | шанс x5, количество x2 | то же |
| Рейд-боссы | шанс x2 | дроп с РБ — основа экономики, x10 обвалит цены за неделю |
| Квесты | награда x10, дроп x5 | квесты не должны отставать от общего темпа |
| Расход шотов | **x1** | ретейл: иначе рушится экономика D–C грейда |
| Заточка | **ретейл** | самый быстрый способ убить экономику — смягчить заточку |
| Автолут | выключен, травы — включены | классик, но траву в бою физически не поднять |
| Скиллы | учатся за SP | классик |

Поменять любое значение — правь профиль и выполняй `make configure`,
перезапускать сервер не обязательно для части настроек, но надёжнее
`make restart`.

Посмотреть, что изменится, ничего не трогая:

```bash
./scripts/configure.sh --dry-run
```

Вернуть ретейл x1 для проверки «это баг сборки или рейты?»:

```bash
./scripts/configure.sh --profile retail-x1
```

### Почему настройки — профилем, а не правкой конфигов

Соблазн велик: открыть `dist/game/config/Rates.ini` и поправить руками.
Проблема вылезает при первом же обновлении эмулятора — сборка перезапишет
конфиги, и все правки пропадут. Или, хуже, останутся, но с устаревшими
ключами, и сервер молча заработает не так, как ты думаешь.

Профиль правит **только перечисленные ключи**, переживает обновления и
показывает отчёт: что изменено, чего в сборке не нашлось. Обязательные ключи
(`!RateXp`) при отсутствии дают ошибку, а не тихий пропуск, — так
несовместимость профиля со сборкой видна сразу, а не через месяц по жалобам.

Подробности формата — [`config/profiles/README.md`](config/profiles/README.md).

## Повседневная работа

```bash
make status              # контейнеры, порты, онлайн, паузы GC
make logs                # логи игрового сервера
make online              # кто в игре
make backup              # копия баз (безопасно на живом сервере)
make restart             # перезапуск с корректным сохранением персонажей
```

Полный список — `make` без аргументов. Подробно — [docs/OPERATIONS.md](docs/OPERATIONS.md).

Резервные копии настрой сразу, до открытия сервера. Строка в cron:

```cron
0 5 * * * cd /путь/к/l2-interlude-x10 && ./scripts/backup.sh >> logs/backup.log 2>&1
```

## Структура

```
.env                    твои настройки (пароли, IP, рейты) — не в git
docker-compose.yml      база + логин-сервер + игровой сервер
Makefile                все команды

config/profiles/        профили настроек
  x10-classic.conf        рейты x10
  retail-x1.conf          эталон x1 для сравнения
  _network.conf           сеть и БД, подставляется из .env

scripts/
  build-server.sh         скачать исходники и собрать
  configure.sh            применить профили
  apply-config.py         патчер .ini по ключам
  db-setup.sh             создать и наполнить базы
  account.sh              ГМ, баны, онлайн
  backup.sh               копии и восстановление
  status.sh               состояние сервера
  tests/                  тесты стенда (make test)

jvm/                    флаги JVM: отдельно для игрового и логин-сервера
mysql/my.cnf            настройки MariaDB под нагрузку L2J
docs/                   подробные руководства
dist/                   собранный сервер (создаётся make build)
  game/                   игровой сервер: config, data, логи
  login/                  логин-сервер
  libs/                   jar-ы, общие для обоих
  db_installer/sql/       дампы базы
```

## Правовая сторона

Lineage 2 принадлежит NCSoft. Эмуляторы — независимые программы с открытым
кодом, но запуск частного сервера нарушает пользовательское соглашение NCSoft,
а распространение клиента игры — нарушение авторских прав. Для домашнего
сервера, обучения и экспериментов это обычная практика; публичный сервер с
донатом — совсем другая история и другие риски. Клиент игры каждый игрок
должен получать сам.
