# Сквозная проверка

Прогоняет живой сценарий: настоящий клиент в браузере против настоящего
сервера. Аня входит по номеру телефона, Боря пишет ей через WebSocket, Аня
видит чат и отвечает из приложения.

Юнит- и интеграционные тесты проверяют части по отдельности; здесь проверяется,
что они сходятся: Flutter → REST → WebSocket → Go → Postgres и обратно.

## Как запустить

```bash
# 1. Инфраструктура и сервер
make up
TITO_CORS_ORIGINS=http://localhost:8090 make run

# 2. Веб-сборка клиента
cd app && flutter build web --release --dart-define=TITO_API=http://localhost:8080

# 3. Раздача сборки (отдельный терминал)
python3 e2e/serve.py app/build/web 8090

# 4. Сам прогон
cd e2e && npm install && npm test
```

Скриншоты каждого шага складываются рядом со скриптом.

## Снимок всех экранов

`make shots` проходит **оба** клиента на двух ширинах — 430 и 1280 — и
снимает каждый экран: вход, список, переписку, группу, избранное, поиск,
настройки, сведения о чате и остальное. Поверх кадров собираются
**контактные листы** — по одной картинке на клиента, все экраны сразу.
Отдельные кадры смотреть невозможно: глаз теряет, что с чем сравнивать.

```bash
make up
TITO_CORS_ORIGINS=http://localhost:8090,http://127.0.0.1:4173 make run

make app-web  &&  python3 e2e/serve.py app/build/web 8090   # Flutter
make web-build && (cd web && npx vite preview --port 4173)  # веб-клиент

make shots                 # оба клиента
make shots ONLY=flutter    # только один
```

Кадры ложатся в `docs/shots/` — это вывод, он не в репозитории.

Следом `e2e/palette.py` сверяет цвета **по самим кадрам** с
`web/src/styles.css`: считает, сколько какого цвета в снимке переписки, и
проверяет, что главные — из палитры. Глазами эту разницу не поймать,
#121A22 и #0B1117 на экране почти одинаковы. Координатами тоже нельзя:
один раз я так промахнулся мимо пузыря и получил цвет, которого в палитре
нет вовсе.

### Почему кнопки ищутся по `role=button`

Flutter после клика мышью показывает подсказку кнопки и держит её, пока
указатель на месте. Подсказка — отдельный узел дерева с тем же текстом:
следующий клик уходил в неё, кнопка не срабатывала, и выглядело это как
зависший экран. Поэтому нажатие ищет узел с `role="button"`, а после клика
указатель уводится к правому краю — не в левый верхний угол, там стрелка
«Назад».

## Почему всё так странно устроено

Flutter рисует интерфейс в канвас, поэтому кнопок и полей в DOM нет.
Скрипт включает дерево доступности — тогда появляются узлы `flt-semantics`
с текстом, по которым можно кликать. Текст вводится клавиатурой, а не
подстановкой в `input`: подменённое напрямую значение движок не заметит.


## Если сценарий встал на входе

Сервер ограничивает выдачу кодов: три на номер за десять минут и двадцать
на адрес за час. Один прогон съедает два кода, но несколько подряд —
упираются в лимит, и сервер отвечает `429`. На экране это выглядит так,
будто приложение не отвечает на нажатие: экран просто не меняется.

Сценарий печатает такие отказы (`сервер ответил 429 на /v1/auth/request-code`).
Сбросить счётчики: `redis-cli -p 6380 FLUSHDB`.

## Звонок

```bash
make e2e-call
```

Два окна браузера, настоящий сервер, настоящий WebRTC. Проверяется не
«кнопка нажалась», а то, ради чего звонок нужен: у собеседника звонит
телефон, после ответа встаёт соединение и по нему идёт звук в обе стороны.
Последнее видно только по счётчикам RTP — соединение умеет встать и молчать.

Запускается через `xvfb-run` не для красоты: в headless браузер отказывает
в микрофоне даже с подменённым устройством. Звуковых устройств в сборочном
контейнере нет вовсе, поэтому `getUserMedia` подменяется дорожкой от
осциллятора — всё остальное в звонке идёт как у людей.

## Звонок из приложения

```bash
make e2e-call-app
```

Приложение звонит в веб-клиент. Сборка Flutter для веба берёт тот же
`CallService`, что и APK, — разница только в реализации WebRTC под
платформу, так что проверяется именно код приложения. Заодно проверяется
маска номера: набираются десять цифр, а в поле должно получиться
`+7 (900) 123-45-67`.

Серверу нужно разрешить оба адреса:
`TITO_CORS_ORIGINS=http://127.0.0.1:4173,http://127.0.0.1:8090`.

## Состав группы и удаление

```bash
make e2e-groups
```

Два окна: владелец группы и обычный участник. Сервер проверяет права своими
тестами; здесь проверяется вторая половина — интерфейс не показывает того,
чего человеку нельзя, и показывает то, что можно. Заодно проверяется, что в
группе нет кнопки звонка: групповым звонкам нужен отдельный сервер сведения
потоков, и кнопка, которая всегда отвечает отказом, хуже её отсутствия.
