# Развёртывание

Один сервер, пять контейнеров: Postgres, Redis, MinIO, сам сервер и Caddy.
Наружу смотрит только Caddy — он же выпускает сертификаты и отдаёт
веб-клиент. Всё остальное живёт во внутренней сети и портов на хост не
открывает.

Машины хватит небольшой: два ядра и два гигабайта памяти. Узкое место —
не процессор, а диск под переписку и файлы.

---

## Что нужно до запуска

**Три имени в DNS**, все на адрес этой машины:

| Имя | Зачем |
|---|---|
| `домен` | веб-клиент |
| `api.домен` | REST и WebSocket |
| `media.домен` | вложения |

Записи должны существовать **до** первого запуска: Let's Encrypt проверяет
их по 80 порту, и без этого сертификата не будет. Порты 80 и 443 обязаны
быть открыты.

**Ключ sms.ru.** Без него сервер поднимется, но коды подтверждения будут
уходить в лог вместо телефона — войти не сможет никто. Это единственная
внешняя услуга, без которой мессенджер не работает вовсе.

## Запуск

```bash
git clone <репозиторий> tito && cd tito
cp deploy/env.example deploy/.env
```

Заполнить `deploy/.env` — там сказано, что откуда берётся. Секреты
генерировать, а не придумывать:

```bash
openssl rand -base64 48   # TITO_JWT_SECRET
openssl rand -base64 24   # TITO_PG_PASSWORD
openssl rand -hex 16      # TITO_S3_SECRET_KEY
```

Затем:

```bash
make deploy-up
```

Первая сборка занимает несколько минут: собираются сервер и веб-клиент.

**Сервер перезапустится два-три раза** — это нормально. Он обращается к
хранилищу по публичному имени, а Caddy в этот момент ещё получает
сертификат. Как только тот выпущен, сервер поднимется и создаст бакет сам.
Если перезапуски не прекращаются больше пяти минут — смотреть логи Caddy,
почти наверняка не сошлись DNS.

Проверка:

```bash
curl https://api.домен/healthz     # 200
make deploy-logs                    # хвост логов
```

## Обновление

```bash
git pull
make deploy-up      # пересоберёт изменившееся и перезапустит
```

Миграции базы применяются при старте сервера сами, отдельного шага нет.

Адрес API зашивается в сборку веб-клиента — это не переменная окружения, а
подстановка Vite. Поэтому смена домена требует пересборки образа, а не
правки настроек.

## Что нужно знать про устройство

**Подпись ссылок на файлы.** Вложение отдаётся по временной ссылке,
подписанной вместе с именем хоста. Поэтому `MINIO_SERVER_URL` в compose,
`TITO_S3_ENDPOINT` у сервера и домен в `Caddyfile` обязаны совпадать до
буквы. Разойдутся — вложения перестанут открываться, а в браузере это будет
выглядеть как «файлы пропали», хотя они на месте.

**Обращение сервера к хранилищу** идёт по тому же публичному имени, но не
выходит наружу: у контейнера Caddy прописаны псевдонимы `api.домен` и
`media.домен` внутри сети Docker.

**Настоящий адрес клиента** приходит из `X-Forwarded-For`, и сервер ему
доверяет (`TITO_TRUST_PROXY=true`). Это верно ровно потому, что перед ним
стоит свой Caddy. Если поставить сервер наружу напрямую, доверие надо
снять: иначе любой клиент подделает свой адрес и обойдёт лимиты на коды.

**Redis без сохранения на диск** намеренно: в нём только присутствие,
лимиты и рассылка событий. Переписка и коды подтверждения — в Postgres.

## Резервные копии

Автоматики нет — это надо завести самому. Копировать нужно два тома:

```bash
# База
docker exec tito-postgres-1 pg_dump -U tito tito | gzip > tito-$(date +%F).sql.gz

# Файлы
docker run --rm -v tito_miniodata:/data -v "$PWD":/out alpine \
  tar czf /out/media-$(date +%F).tar.gz -C /data .
```

Проверять восстановление, а не только снятие: копия, которую никогда не
разворачивали, — это не копия.

## Чего в этой сборке нет

Честный список, чтобы не выяснять это в бою:

* **Пуш-уведомлений.** На сервере стоит заглушка (`push.NoopPusher`):
  сообщения доходят, пока приложение открыто. Для доставки при закрытом
  приложении нужен FCM или свой шлюз — интерфейс для него готов,
  реализации нет.
* **Перевода.** `POST /v1/ai/translate` отвечает `503
  translate_not_configured`, пока не подключён поставщик.
* **Метрик и трассировок.** Есть только логи в stdout — их собирает
  docker.
* **Ограничения частоты команд в сокете.** Лимиты стоят на выдачу кодов,
  но не на поток сообщений в уже открытом соединении.
* **Уборки осиротевших файлов.** Удалённое сообщение не удаляет вложение
  из хранилища.

Ничего из этого не мешает запуститься, но каждое стоит завести до того,
как людей станет много.
